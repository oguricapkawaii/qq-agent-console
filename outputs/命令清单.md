### /task

用法：`/task <agent> [--backend ID] [--model 模型] [--effort 强度|default] [--mode text|read|edit|exec] [--dir "路径" | --find "关键词"] -- <任务正文>`

子命令：`all`、`status`、`result`、`cancel`

| 选项 | 说明 | 取值 |
|---|---|---|
| `--backend` | 指定执行后端 ID（默认取 Agent 的默认后端） | `<后端ID>` — |
| `--model` | 指定模型（默认取你的保存选择或 Agent 默认） | `<模型>` — |
| `--effort` | 推理强度；default 表示模型默认 | `<强度|default>` — |
| `--mode` | 执行权限：text 文本 / read 只读 / edit 读写 / exec 读写+受控命令 | `<text|read|edit|exec>` `text`、`read`、`edit`、`exec` |
| `--dir` | 任务目录：绝对路径或已绑定目录；"." 表示本群×你当前绑定的目录 | `<路径>` — |
| `--find` | 按关键词在授权搜索根内查找目录；返回候选后需选择 | `<关键词>` — |

示例：
- `/task deepseek -- 解释这段需求`
- `/task all -- 分别给出建议`
- `/task zcode --dir "/Users/example/Documents/项目" --mode edit -- 更新 README 的安装说明`
- `/task codex --find "记账项目" --mode exec -- 修复并运行测试`
- `/task status 1a2b3c4d`
- `/task result 1a2b3c4d`
- `/task cancel 1a2b3c4d`

说明：
- 不带目录选择器也没有 mode 时是纯文本；给出 --dir/--find 而省略 mode 时默认 read。
- --dir . 表示本群×你当前绑定的目录，不会回落到进程工作目录。
- 正文里的任何内容都不会被当成权限；正文说“修改”也不会升级权限。


### /workspace

用法：`/workspace find <关键词> | use "绝对路径" | status | clear | select <确认码> <序号>`

子命令：`find`、`use`、`status`、`clear`、`select`

示例：
- `/workspace find 记账项目`
- `/workspace select AB12CD34 1`
- `/workspace use "/Users/example/Documents/项目"`
- `/workspace status`
- `/workspace clear`

说明：
- find 只在配置的授权搜索根内查找，限制深度、候选数与耗时，不扫描整机。
- 即使只有一个候选也必须由本人 select；确认码绑定群、发起人、请求与 TTL。


### /agent

用法：`/agent list | models <agent> | set <agent> [--model 模型] [--effort 强度|default] [--backend ID] | status [agent] | clear <agent>`

子命令：`list`、`models`、`set`、`status`、`clear`

| 选项 | 说明 | 取值 |
|---|---|---|
| `--model` | 保存为该 Agent 的默认模型 | `<模型>` — |
| `--effort` | 保存为该 Agent 的默认强度；default 表示模型默认 | `<强度|default>` — |
| `--backend` | 保存为该 Agent 的默认后端 | `<后端ID>` — |

示例：
- `/agent list`
- `/agent models deepseek`
- `/agent set deepseek --model <可用模型> --effort <支持的强度>`
- `/agent set deepseek`
- `/agent status`
- `/agent clear deepseek`

说明：
- 模型与强度必须真实存在于该后端目录中，否则拒绝保存。
- 目录授权不在这里保存：目录只有 /workspace 绑定与显式 --dir 两种来源。


### /team

用法：`/team create <目标> | add <团队ID> <步骤ID> <agent> [选项] -- <本步任务> | remove <团队ID> <步骤ID> | plan <团队ID> | run <团队ID> | status [团队ID] | result <团队ID> [步骤ID] | cancel <团队ID> | retry <团队ID>`

子命令：`create`、`add`、`remove`、`plan`、`run`、`status`、`result`、`cancel`、`retry`

| 选项 | 说明 | 取值 |
|---|---|---|
| `--backend` | 指定执行后端 ID（默认取 Agent 的默认后端） | `<后端ID>` — |
| `--model` | 指定模型（默认取你的保存选择或 Agent 默认） | `<模型>` — |
| `--effort` | 推理强度；default 表示模型默认 | `<强度|default>` — |
| `--mode` | 执行权限：text 文本 / read 只读 / edit 读写 / exec 读写+受控命令 | `<text|read|edit|exec>` `text`、`read`、`edit`、`exec` |
| `--dir` | 任务目录：绝对路径或已绑定目录；"." 表示本群×你当前绑定的目录 | `<路径>` — |
| `--find` | 按关键词在授权搜索根内查找目录；返回候选后需选择 | `<关键词>` — |
| `--after` | 本步的直接依赖步骤 ID，逗号分隔 | `<步骤ID,步骤ID>` — |

示例：
- `/team create 修复项目问题并验证`
- `/team add t1a2b3c4 inspect deepseek --mode read --dir "/Users/example/Documents/项目" -- 分析问题`
- `/team add t1a2b3c4 fix zcode --after inspect --mode edit --dir "/Users/example/Documents/项目" -- 修改文件`
- `/team plan t1a2b3c4`
- `/team run t1a2b3c4`
- `/team result t1a2b3c4`
- `/team retry t1a2b3c4`

说明：
- add 的公共选项与 /task 完全相同，只多一个 --after；未写 mode/dir 的步骤默认纯文本。
- run 前冻结每步 backend/model/effort/mode/规范目录；未选完目录时计划保持 draft。
- 同目录步骤互斥；需要确定先后顺序必须显式写 --after。
