# QQ机器人操作指南

更新日期：2026-10-12（Asia/Shanghai）。面向当前已上线的统一控制台。日常使用先看第1–7节；维护看第10–12节。总览见[项目总架构说明](项目总架构说明.md)。

## 1. 先认识当前可用入口

| Agent名字 | 后端 | 当前默认模型 |
|---|---|---|
| deepseek | DeepSeek Harness | deepseek-flash |
| zcode | ZCode | glm-5.3 |
| codex | Codex本机登录 | gpt-6.1-sol |

模型和推理强度以 `/agent models <agent>` 的实际目录为准，默认可由你保存的选择覆盖。当前OpenAI/GLM独立API入口未启用；不要把 `gpt` 当作当前可用入口。当前没有启用自定义preset。

QQ登录由NapCat维持。机器人进程和HTTP健康正常，不一定代表QQ仍在线；登录失效时需要账号持有人手机确认。

## 2. 30秒上手

在已授权群、使用已授权账号发送：

```text
/help
/agent list
/task deepseek -- 解释这段需求
/task zcode -- 整理一个实施清单
/task codex -- 评审这个方案
```

先用文本任务确认正常收到结果，再使用目录任务。下面的 `<任务ID>`、`<团队ID>`、`<确认码>`、模型与路径占位符必须替换为实际值；示例目录必须存在并已经授权。

## 3. 命令总览与选项

| 命令族 | 用途 |
|---|---|
| `/task` | 提交任务、all、status、result、cancel |
| `/workspace` | find、use、status、clear、select |
| `/agent` | list、models、set、status、clear |
| `/team` | create、add、remove、plan、run、status、result、cancel、retry |
| `/confirm` | 消费本人一项受控操作的确认码 |
| `/access` | add、remove、list；本群管理员授权管理 |
| `/command` | list、show；查看精确用法，不调用模型 |
| `/help` | 总帮助或指定命令族帮助 |

精确规格见[自动生成命令清单](命令清单.md)。旧模型/read/write/all等口令已停用，只提示迁移；统一使用上述入口。

任务格式：

```text
/task <agent> [公共选项] -- <任务正文>
```

| 选项 | 用法 |
|---|---|
| --backend | 指定该Agent可用后端ID |
| --model | 指定目录中存在的模型 |
| --effort | 指定支持的强度；default使用模型默认 |
| --mode | text/read/edit/exec |
| --dir | 指定绝对目录，或用已绑定目录 `.` |
| --find | 在授权搜索根内按关键词查找目录 |

选项写在分隔符 `--` 之前；之后的正文原样保留。未知/重复选项、缺值、dir与find同时出现、text配目录会拒绝。正文说“帮我修改”不会自动取得写权限。

## 4. 文本、模型选择与结果查询

```text
/agent models codex
/agent set codex --model gpt-6.1-sol --effort low
/agent status codex
/task codex --mode text -- 帮我解释这个问题
/task all -- 分别给出建议
/task status
/task status <任务ID>
/task result <任务ID>
/task cancel <任务ID>
/agent clear codex
```

优先级：本次显式选项 > 你保存的默认 > Agent/后端默认。不同模型支持的强度不一定相同；不支持时明确拒绝，不偷偷换模型。

all只做多个已启用Agent的独立文本回答，不接受目录/模式/模型选项，不是团队流水线。共享聊天上下文开启时可能串行执行。

clear清除“本群×你×该Agent”的普通聊天上下文，不删除任务/团队审计。团队不读取普通聊天历史。

## 5. 文件读取、修改和执行测试

| 模式 | 适合什么 |
|---|---|
| text | 纯对话，不提供文件工具 |
| read | 看目录、搜索、读取文本，不修改文件 |
| edit | 创建/修改授权文件，保留差异、哈希和备份 |
| exec | 在系统沙箱内执行白名单本地命令，同时具有相应读写能力 |

```text
/task deepseek --mode read --dir "/Users/example/Documents/你的项目" -- 阅读README和目录结构，说明设计
/task zcode --mode edit --dir "/Users/example/Documents/你的项目" -- 只更新README的安装说明，报告实际修改
/task codex --mode exec --dir "/Users/example/Documents/你的项目" -- 运行项目已有的获准测试，报告退出码和输出
```

不带目录和mode默认为text；带目录而省略mode默认为read。显式文件模式但省略目录时使用本人当前绑定；没有绑定则拒绝。明确路径且已授权时直接执行，不是每次edit都需要confirm。

操作范围受用户/群授权、最具体目录ACL、任务模式、后端能力与全局策略共同限制。机器人自身源码、配置、数据库和凭据受保护；目录绑定不会扩大权限。

修改前后以实际变更清单和文件哈希为准。外部修改导致版本漂移时拒绝覆盖；覆盖/删除前备份到受控备份根，不把同目录`.bak`当作可靠备份。多文件任务可能部分完成，不承诺整体自动撤销。

exec不是任意终端：禁提权、禁额外网络、限制可执行文件与参数；凭据/受保护目录不可读写。任务目录和私有临时目录可写，另仅放行空设备 `/dev/null`，供pytest等初始化使用。系统库/解释器只读可用；PATH由启动环境提供项目venv。平台不能提供可验证隔离时exec明确不可用，不降级为裸执行。

读取有文件与累计大小预算，二进制/超大输入可能被拒绝；超出范围时缩小文件集或改用搜索，不要求解除安全策略。

## 6. 找目录与绑定目录

直接绑定一个已授权的明确目录：

```text
/workspace use "/Users/example/Documents/你的项目"
/workspace status
/task deepseek --dir . --mode read -- 说明主要模块
/workspace clear
```

`.`仅代表“本群×你”绑定的目录，不回落到机器人工作目录。

先查找再绑定：

```text
/workspace find 项目关键词
/workspace select <确认码> 1
```

结合任务查找并续跑：

```text
/task zcode --find "项目关键词" --mode edit -- 补充README的安装步骤
/workspace select <确认码> 1
```

即使只有一个候选也要本人选择；期限以机器人回执为准。确认一次性，绑定群/用户/原请求/候选快照，过期、跨身份或目录变化会拒绝。独立workspace查找只绑定目录；任务发起的查找在选择后续跑原任务。选择前不调用模型、不改文件。

同目录及父子目录任务互斥；无关目录可并行。需要业务顺序时用团队依赖，目录锁不能替代依赖关系。

## 7. 三个后端一起工作

```text
/team create 分析问题、最小修改并验证
/team add <团队ID> inspect deepseek --mode read --dir "/Users/example/Documents/你的项目" -- 阅读相关文件，给出问题与最小修复方案
/team add <团队ID> fix zcode --after inspect --mode edit --dir "/Users/example/Documents/你的项目" -- 根据直接上游结果实施最小修改
/team add <团队ID> verify codex --after fix --mode exec --dir "/Users/example/Documents/你的项目" -- 运行项目获准测试，报告真实退出码和输出
/team plan <团队ID>
/team run <团队ID>
/team status <团队ID>
/team result <团队ID>
```

create返回真实团队ID后，替换后续所有占位符。先看plan再run，核对目录、模式、模型、后端与依赖；add同一步骤ID会完整替换该步骤。删除被依赖步骤会被拒绝。

run冻结执行规格；之后改默认模型或目录绑定不改变这一轮。目录尚未选择时不允许部分启动。上游结果只是数据，不提高后续权限；每步只拿到目标、本步和直接依赖结果，不读取兄弟步骤或普通聊天历史。

```text
/team result <团队ID> verify
/team cancel <团队ID>
/team retry <团队ID>
```

取消保留已经完成的结果和实际文件修改。只有失败/中断团队可按规则重试，取消不能retry；成功结果复用需核验文件未漂移。失败exec或已部分写入的edit可能要求 `/confirm <确认码>`，先审阅副作用清单。

重启后未完成业务标记interrupted，不自动继续；旧内存确认码失效。需要继续时先核对现有文件，再显式重试。

## 8. 怎么判断真的做完了

| 状态 | 解释 |
|---|---|
| queued / running | 排队或执行中，受任务期限限制 |
| awaiting_selection / awaiting_confirmation | 需要本人选择目录或确认列出的受控操作 |
| succeeded | 服务端记录的任务成功；文件变更/命令结果应继续查看 |
| no_change | 会话结束但未记录实际操作，不能当作已修改 |
| failed | 执行/协议/提交等失败，可能已有部分文件副作用 |
| cancelled | 已取消，已应用文件不会自动恢复 |
| interrupted | 服务重启造成中断，不自动重跑 |

read需要实际读取动作，edit看实际提交和文件变化，exec看命令回执的退出码/输出。一次run_command动作成功执行不意味着其中测试通过；例如测试退出码非0仍要按测试失败处理。

同一QQ消息重放不会再次执行已登记任务；失败或取消也不自动重跑。发出一条新消息会获得新的message_id，即便正文相同也可能新建任务，勿连续重复发送。有意重试先查已有结果和副作用。

## 9. 授权与HTTP接口

管理员使用 `/access add <成员账号>`、`/access remove <成员账号>`、`/access list` 管理本群文本授权。文件权限还需配置对应目录ACL；管理员身份不是全盘访问权。

当前业务HTTP API关闭，访问业务路径会返回 `503 api_disabled`；QQ可正常使用。HTTP `/healthz` 与 `/status` 是健康/状态入口，不是QQ口令。Token、scope、归属、幂等与真实应用装配已在隔离端点验证。

需要启用业务API时按专门变更处理：配置可信Token身份和scopes、保持本机监听或另行设计访问边界、核验重启影响。不要把Token写进QQ消息或公开文档。当前没有为本次文档更新启用API或新增Token。

## 10. 日常排错

| 现象 | 优先检查 |
|---|---|
| QQ没有回执 | NapCat账号是否登录、OneBot是否online/good、机器人连接是否恢复；仅health200不够 |
| 需要扫码 | 使用已有NapCat WebUI `http://127.0.0.1:6099/webui/`，按手机QQ确认；不要公开passkey或二维码 |
| 模型/强度不支持 | 用agent models查看真实目录；不要猜模型名 |
| 未知Agent | 用agent list；当前入口是deepseek、zcode、codex |
| 路径不授权/受保护 | 核对实际目录ACL；use只能绑定已授权目录 |
| dir点号不可用 | 先查看workspace status，再绑定目录 |
| 目录忙 | 等现有任务收敛；团队使用明确after依赖 |
| 确认无效/过期 | 重新发起查找或受控操作，不能复用旧码 |
| 文件冲突/部分失败 | 查看变更清单、实际文件与备份；先重新读取，不强制覆盖 |
| no_change/无实际动作 | 不是完成修改；查看result，缩小任务或修正指令后再决定重试 |
| exec不可用/命令拒绝 | 核对平台隔离与白名单；不要求取消沙箱或开任意Shell |
| 后端超时/连接错误 | 先检查具体后端登录、配置、CLI与网络；不凭错误自述认定已修改 |

取消不能保证恢复成任务开始前的文件状态。重试前审阅已经发生的变化。

## 11. 启动、备份与维护

当前项目位于 `/Users/example/Documents/qq机器人`，使用项目venv启动 `app.main`，单实例/单worker、无reload。**正常使用不用再启动一份机器人。**

只读健康检查：

```bash
curl -fsS http://127.0.0.1:8080/healthz
```

详细维护见维护与恢复执行卡（本机归档，未上传）。旧 `runtime/state/restart_bot.sh` 禁止使用，历史切换程序绑定旧PID，也不能直接重跑。

维护前核验PID、启动时间、完整命令、cwd、监听与DB句柄，等待活动任务/团队/确认收敛；一致性备份后只优雅停止已核实实例，不强杀、不按同名进程清理。退出和端口释放后再一次启动。

数据库运行中备份必须用SQLite backup API，不能只复制 `bot.db` 漏掉WAL。封存原件与演练副本分开，验证完整性和既有行内容。配置schema_version=2与数据库schema_meta=3不是同一版本概念。

代码回退与数据库恢复分别评估；不自动恢复数据库覆盖新增业务。当前已知版本恢复点见最终切换恢复点（本机归档，未上传）。历史事故前旧构建身份尚未证明，不能以改DB版本数字替代恢复。

本手册示例只是文档文本；不要把包含示例的整份Markdown复制到终端执行。生成文档与执行维护应分开。
